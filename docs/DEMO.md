# Demo guide ХьюманЛИ

## Цель demo

За две минуты зритель должен понять: ХьюманЛИ управляет полным коммуникационным циклом, а не просто генерирует письмо. Он видит Inbox, коммуникационный контекст, объяснимое решение, follow-up, auto-close и human escalation.

## Preflight · до выхода на сцену

- Открыть свежую вкладку ХьюманЛИ и проверить seed: Дмитрий, Елена, Игорь.
- Для основной защиты открыть опубликованную [GitHub Pages-демо](https://spnkd.github.io/hyumanli-hr-assistant/): backend уже подключён, ручная подготовка не нужна.
- Публичный provider badge ожидаемо показывает `AI Live · BotHub / deepseek-v4-flash`; при временной ошибке можно продолжить с `Demo fallback · offline-ready`.
- Для локального прогона можно запустить `node server.js`; это отдельный OpenRouter/Qwen proxy с ключом только в `.env`.
- Для полностью автономного demo можно открыть `index.html` напрямую: DemoProvider покрывает тот же workflow без сети.
- Если состояние изменилось, открыть **Настройки → Сбросить demo data**.
- Закрыть DevTools и лишние вкладки.

## Режиссёрский flow · максимум 2 минуты

### 00:00–00:12 · Communication Inbox

**Клик:** **Коммуникации**.

**Показать:** summary и строки с `Следующее действие`.

**Сказать:** «Это не список писем, а рабочий inbox HR: здесь видно состояние каждого кейса и ближайший шаг».

### 00:12–00:30 · Communication Memory

**Клик:** открыть Дмитрия.

**Показать:** карточку **Коммуникационный профиль** — короткий стиль, 1–2 дня, окно 10:00–12:00, последние темы.

**Сказать:** «Персонализация — это не имя в шаблоне. Система учитывает предыдущий коммуникационный контекст».

### 00:30–00:45 · Decision Engine

**Клик:** **Почему так?**.

**Показать:** reason codes и Communication check.

**Сказать:** «До генерации текста понятно, почему выбран именно этот шаг и почему сообщение можно отправлять».

### 00:45–01:00 · Запуск

**Клик:** **Новая коммуникация → Запустить коммуникацию**. Оставить defaults: Дмитрий, eNPS, +5 дней, поддерживающий тон.

**Показать:** первое письмо и provider badge `AI Live` или `Demo fallback · offline-ready`.

**Сказать:** «AI формулирует сообщение, но workflow не зависит от доступности сети».

### 01:00–01:25 · Timing и follow-up

**Клик:** `+3д`, затем `+1д`, затем ещё `+1д`.

**Показать:** перенос из-за выходных и статус `Follow-up отправлен`.

**Сказать:** «Система не просто ждёт фиксированные три дня: она выбирает допустимое рабочее окно и не отправляет в выходной».

### 01:25–01:43 · Response и auto-close

**Клик:** **Симулировать ответ → Ответить и закрыть цикл**.

**Показать:** `Ответ получен`, будущие события `Архивировано`.

**Сказать:** «После ответа будущие напоминания закрываются автоматически — HR не делает cleanup вручную».

### 01:43–02:00 · Human escalation

**Клик:** **Коммуникации → Игорь**.

**Показать:** `Нужен личный контакт`, `repeated_non_response`, explanation Decision Engine.

**Сказать:** «Если автоматических касаний уже достаточно, ХьюманЛИ не превращает их в spam — он передаёт разговор человеку».

## Optional proof-point · 15 секунд

**Новая коммуникация → Свой фокус → «обсудить компенсацию» → Запустить.**

Показать `Нужно подтверждение` и кнопку `Подтвердить действие`. Сказать: «Sensitive topic не уходит в автопилот: система готовит текст, но оставляет решение HR».

## Fallback

- При missing key, network/API error, timeout или invalid JSON Live AI переходит в DemoProvider.
- В UI остаётся provider indicator, техническая ошибка не ломает workflow.
- Не обещать реальную доставку email, calendar integration или production compliance: это границы MVP.
